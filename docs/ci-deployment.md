# Change or add an ingestion deployment

Read [AGENTS.md](../AGENTS.md), the [deployment skill](../.claude/skills/deploy-scheduled-ingestion/SKILL.md), and, for Terraform, the [protected apply skill](../.claude/skills/protected-terraform-apply/SKILL.md). This procedure includes private usage telemetry; source behavior belongs in the owning job's README.

1. **Declare scope and ownership.** Name the target, resources and intended outcome. Follow [agent integration](agent-integration.md) for overlapping work and [publication readiness](publication-readiness.md) before expensive real-release work. New assets/pipelines require admission evidence and a feature identity decision under AGENTS.md.
2. **Register the producer.** `DEPLOY_TARGETS` in [`ingestion_targets.py`](../scripts/ingestion_targets.py) owns resource scope, runtime window, canary policy and verification hook. Its constructor rejects incompatible policies; `TARGETS` excludes telemetry. Use a thin `<target>-deploy.yml` wrapper around `ingestion-deploy.yml`; keep shared publication claims and installed identity state intact.
3. **Connect the deployment.** [`terraform-targets.json`](../.github/terraform-targets.json) owns deployment workflows/images, `terraform_prerequisites`, registered apply scopes and installed image checks. The same prerequisite graph must match CI callers' `needs` and conditional success gates; it orders selected owners without requesting unrelated mutations. Add resources using the [target-change procedure](terraform-reconciliation.md#change-a-terraform-or-iam-target). Selection follows workflows, nested actions, invoked scripts, Docker COPY and parsed Terraform ownership/modules. `selection_exceptions` owns reasoned traversal boundaries and input additions. Executor-only `exclude` entries replace inferred callers with explicit representative `deployments`: sea ice for ingestion, Artifact Registry IAM for shared Terraform, and the viewer/CDN's own executors. Validation remains mandatory. The Terraform registry and variables are deployment content and conservatively select all consumers. Content changes retain their actual consumers and images. Admission entrypoints stop traversal because their imports do not produce deployment content.
4. **Exercise the boundary.** Run focused positive and refusal tests for selection, prerequisites, plan scope and runtime verification. Production recipes and Terraform image consumers determine image bindings; register probes under `image_checks`. Missing typed executor environment keys fail before authentication. Every selected deployment retains its image validation floor, including hold-only releases. Use complete synthetic runtime/serialization batches for publication-code changes without a real release, and the production conversion chain for native changes. Follow [image contracts](deployment-contracts.md#images-and-execution) for CPU, memory, timeout and scratch; installed probes have no network/source mounts and use memory-backed `/tmp`. WDPA's 12-hour task timeout covers its observed 8 h 21 m maximum. Release at most one held ingestion target per change.
5. **Validate and review.** Follow [validation before push](ci-preflight.md#validate-before-push). Include expected actions, scope/permission coverage and unverified live prerequisites. Production mutations require `jonaraphael` review, merge to `main` and the protected `shared-datasets-production` workflow; local plans are review evidence. AGENTS.md still governs Git operations.
6. **Observe the rollout.** Main `ci-ready` supplies exact tested images by digest; deployments never rebuild missing bytes. Finish registry/IAM bootstrap first. Follow [queue ownership](deployment-contracts.md#serialization-and-protected-execution): preparation and canaries stay outside the state queue. Usage holds one target queue through apply and canary verification. The `dataset-usage` caller owns its signed apply and canary. Ingestion/cleanup IAM read the existing bucket through a data source, so they cannot plan logging/CORS changes and can proceed independently of the usage canary. Other ingestion wrappers retain combined rollout. Recovery/dispatch requires `executor_sha`, `source_run_id` and `source_run_attempt` from the exact successful main-push CI attempt. Deferred verification is not completion.
7. **Report the outcome.** Use the captured canary execution, verify its [terminal outcome](deployment-contracts.md#records-receipts-and-runtime-outcomes) and release/latest contracts (or private usage report/activation), and preserve [failure coverage](alert-routing.md#execution-and-delivery-verification). Report image digest, resource actions, execution/result, changed remote paths and uncertainty. Use [recovery](ci-recovery.md) for failures.

Deployment bootstrap requires the exact merged executor PR and `jonaraphael`'s effective approval of its final head, or restricted self-authored merge acceptance, before candidate checkout/authentication. Missing, ambiguous, stale, dismissed or unreadable acceptance fails closed; direct main pushes cannot authorize deployment. Reusable callers retain `pull-requests: read` through every layer. The credential-free PR check uses the same gate with an explicit PR number and the expected head; deployment-content PRs need owner approval of that exact head before merge. After approving a non-owner PR, the owner uses **Re-run failed jobs** on that unchanged head; only the small `owner-acceptance` job and `ci-ready` rerun. Marking a PR ready for review triggers this check. CODEOWNERS routes Dependabot-touched paths to the owner. The ingestion plan guard installs the locked `ci-plan` parsers before authentication.

Production identities use exact main workflow refs in [`github-workflow-identities.json`](../terraform/envs/prod/github-workflow-identities.json): `job_workflow_ref` for reusable jobs, `workflow_ref` otherwise, with repository/environment constraints. Artifact Registry IAM bootstrap precedes writer rollout; the authoritative WIF binding removes the shared environment subject grant. See [deployment contracts](deployment-contracts.md) for trusted restore, state queues, tested-image handoff and signed receipts.

The bucket-reader can list names and read published objects and pending-publish sources, excluding `000-system/` and production state. Scratch cleanup has exact-leaf listing/conditional pending-publish and cleanup-marker authority; apply workflow identity sync before cleanup. It needs no new authentication variables and has no canonical publisher authority. Observers cannot mutate, administer IAM or access secret versions; [read-only recovery](ci-recovery.md) grants exact production-state reads for planning. Runtime handles image pushes, canaries, schedules and invalidation, then restores observer credentials; reconcilers own private incident state and only the heartbeat identity emits heartbeat logs.

Use [job operations](../.claude/skills/deploy-scheduled-ingestion/references/job-operations.md) for pause/resume, teardown and activation exceptions, the [WDPA runbook](wdpa-monthly-runbook.md) for monthly operations, the [reset runbook](feature-id-reset-installation.md) for first identity installation, and the [usage README](../ingestion/dataset_usage/README.md#activation-and-cost) for activation/cost gates.

## Automatic read-only Terraform PR plans

The owner's 2026-11-05 decision authorizes automatic live planning for same-repository Terraform PRs before `ci-ready`, without an approval click. Application/docs changes skip. Selection and execution resolve the same registered production scopes, including manual IAM owners and removed declarations from the comparison base. Preview-only, lockfile-only and other unregistered Terraform changes emit a skip notice; static checks still apply.

Up to four registered scopes plan concurrently with Terraform **1.8.5**, refreshed state and state-recorded immutable images. Each gets private temporary plan/variable files, removed on success or failure and never uploaded. Resource/action/image allowlists remain per scope. Policy Troubleshooter v3 must grant both overall and allow access, including inherited/conditional grants and deny policies; unknown or unreadable authority fails closed. This does not evaluate principal access boundaries or replace deploy-time checks. Transient policy reads retry three times (5/10-second delays); 4xx and malformed responses fail immediately. Errors identify scope, resource and permission without provider attributes.

The PR identity reads metadata/IAM, the exact default production state object and bucket object names for workspace discovery. It cannot write/lock state, mutate resources, read Secret Manager metadata/policies/versions, sign or impersonate the deployer. Each of the six reviewed secret-bearing `pr_plan_exclusions` emits a notice; static checks and protected planning still apply.

**Same-repository PR authors can read sensitive values persisted in production state.** Forks skip authentication; keep GitHub's fork write-token option disabled because WIF alone cannot distinguish them. Other PR jobs remain credential-free. The separate PR WIF pool requires this repository, `pull_request`, a numeric PR merge ref and exact CI/planner workflow refs. Checkout credentials are not persisted; full history supports comparison-base scope discovery.

Activate through protected `terraform-state-read-iam-sync.yml`: `PR plan identity IAM bootstrap` precedes `PR plan identity provisioning`. Set `GCP_PR_PLAN_SERVICE_ACCOUNT` and `GCP_PR_PLAN_WORKLOAD_IDENTITY_PROVIDER` from sensitive `github_pr_plan_*` outputs, and confirm `GCP_TERRAFORM_SERVICE_ACCOUNT`. Then merge a reviewed PR changing the checked-in `workflow_call.inputs.active.default` in [`pr-terraform-plan.yml`](../.github/workflows/pr-terraform-plan.yml) from `false` to `true`; CI callers must inherit that default. While inactive, the notice succeeds without authentication. Once active, missing configuration and auth/plan/allowlist/permission failures block `ci-ready`; losing a variable cannot deactivate planning. Code alone provisions nothing; local apply is prohibited.
