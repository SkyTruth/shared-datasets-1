# Change or add an ingestion deployment

Read [AGENTS.md](../AGENTS.md), the [deployment skill](../.claude/skills/deploy-scheduled-ingestion/SKILL.md), and, for Terraform, the [protected apply skill](../.claude/skills/protected-terraform-apply/SKILL.md). This procedure includes private usage telemetry; source behavior belongs in the owning job's README.

1. **Declare scope and ownership.** Name the target, resources and intended outcome. Follow [agent integration](agent-integration.md) for overlapping work and [publication readiness](publication-readiness.md) before expensive real-release work. New assets/pipelines require admission evidence and a feature identity decision under AGENTS.md.
2. **Register the producer.** `DEPLOY_TARGETS` in [`ingestion_targets.py`](../scripts/ingestion_targets.py) owns resource scope, runtime window, canary policy and verification hook. Its constructor rejects incompatible policies; `TARGETS` excludes telemetry. Use a thin `<target>-deploy.yml` wrapper around `ingestion-deploy.yml`; keep shared publication claims and installed identity state intact.
3. **Connect the deployment.** [`terraform-targets.json`](../.github/terraform-targets.json) owns deployment workflows/images, `terraform_prerequisites`, registered apply scopes and installed image checks. The same prerequisite graph must match CI callers' `needs` and conditional success gates; it orders selected owners without requesting unrelated mutations. Add resources using the [target-change procedure](terraform-reconciliation.md#change-a-terraform-or-iam-target). Selection follows workflows, nested actions, invoked scripts, Docker COPY and parsed Terraform ownership/modules. `selection_exceptions` owns reasoned traversal boundaries and input additions. Executor-only `exclude` entries replace inferred callers with explicit representative `deployments`: sea ice for ingestion, Artifact Registry IAM for shared Terraform, and the viewer/CDN's own executors. Validation remains mandatory. Content changes retain their actual consumers and images. Admission entrypoints stop traversal because their imports do not produce deployment content.
4. **Exercise the boundary.** Run focused positive and refusal tests for selection, prerequisites, plan scope and runtime verification. Production recipes and Terraform image consumers determine image bindings; register probes under `image_checks`. Missing typed executor environment keys fail before authentication. Every selected deployment retains its image validation floor, including hold-only releases. Use complete synthetic runtime/serialization batches for publication-code changes without a real release, and the production conversion chain for native changes. Follow [image contracts](deployment-contracts.md#images-and-execution) for CPU, memory, timeout and scratch; installed probes have no network/source mounts and use memory-backed `/tmp`. WDPA's 12-hour task timeout covers its observed 8 h 21 m maximum. Release at most one held ingestion target per change.
5. **Validate and review.** Follow [validation before push](ci-preflight.md#validate-before-push). Include expected actions, scope/permission coverage and unverified live prerequisites. Production mutations require `jonaraphael` review, merge to `main` and the protected `shared-datasets-production` workflow; local plans are review evidence. AGENTS.md still governs Git operations.
6. **Observe the rollout.** Main `ci-ready` supplies exact tested images by digest; deployments never rebuild missing bytes. Finish registry/IAM bootstrap first. Follow [queue ownership](deployment-contracts.md#serialization-and-protected-execution): preparation and canaries stay outside the state queue. Usage holds one target queue through apply and canary verification. The `dataset-usage` caller completes the signed apply and canary before native `needs` dependencies release ingestion/cleanup IAM; no polling runner observes nested job names. Other ingestion wrappers retain combined rollout. Recovery/dispatch requires `executor_sha`, `source_run_id` and `source_run_attempt` from the exact successful main-push CI attempt. Deferred verification is not completion.
7. **Report the outcome.** Use the captured canary execution, verify its [terminal outcome](deployment-contracts.md#records-receipts-and-runtime-outcomes) and release/latest contracts (or private usage report/activation), and preserve [failure coverage](alert-routing.md#execution-and-delivery-verification). Report image digest, resource actions, execution/result, changed remote paths and uncertainty. Use [recovery](ci-recovery.md) for failures.

Deployment bootstrap looks up the merged PR for the exact executor SHA before
candidate checkout or authentication. It requires `jonaraphael`'s effective
approval of the final PR head, or records the existing restricted self-authored
merge acceptance. Missing, ambiguous, stale, dismissed and unreadable acceptance
fail closed; successful output records the PR and acceptance evidence. Direct
main pushes cannot authorize a deployment. Callers need read access to PRs and
reviews as well as the existing Actions provenance permissions.
Reusable callers retain `pull-requests: read` through every layer. The ingestion
plan guard installs the locked `ci-plan` parsers before authentication.

Production identities are registered in [`github-workflow-identities.json`](../terraform/envs/prod/github-workflow-identities.json): exact workflow filenames on main, `job_workflow_ref` for reusable jobs, `workflow_ref` otherwise, repository/environment constraints. The separate PR planner requires exact CI/planner refs; advisory PR bucket reads admit only the exact schema-alert leaf at a numeric merge ref after the same-repository gate. Artifact Registry IAM bootstrap provisions the identity manager and workflow identity scope before writer rollout. The authoritative Terraform WIF binding removes the shared environment subject grant.

The bucket-reader identity can list object names and read published dataset/catalog
objects and pending-publish sources, but cannot read `000-system/` objects,
including production Terraform state. Scratch cleanup uses its own exact-leaf
identity: bucket-scoped listing and conditional pending-publish/cleanup-marker
writes, without canonical publisher authority. Apply workflow identity sync before
running cleanup; no new repository authentication variables are needed.

Observer identities cannot mutate resources, administer IAM, read state or access secret versions. Runtime handles image pushes, canaries, schedule control and invalidation; verification restores observer credentials afterward. Reconcilers have separate private incident-state authority; only the safety heartbeat identity emits heartbeat logs. Preserve signing and dataset approval boundaries.

For pause/resume, teardown and activation exceptions, use [job operations](../.claude/skills/deploy-scheduled-ingestion/references/job-operations.md). WDPA operations live in its [monthly runbook](wdpa-monthly-runbook.md), first identity installation in the [reset runbook](feature-id-reset-installation.md), and usage activation/cost gates in its [README](../ingestion/dataset_usage/README.md#activation-and-cost).

## Automatic read-only Terraform PR plans

The owner's 2026-11-05 decision authorizes automatic live planning for same-repository Terraform PRs before `ci-ready`, without an approval click. Application/docs changes skip. Selection and execution resolve the same registered production scopes, including manual IAM owners and removed declarations from the comparison base. Preview-only, lockfile-only and other unregistered Terraform changes emit a skip notice; static checks still apply.

Up to four registered scopes plan concurrently with Terraform **1.8.5**, refreshed state and state-recorded immutable images. Each gets private temporary plan/variable files, removed on success or failure and never uploaded. Resource/action/image allowlists remain per scope. Policy Troubleshooter v3 must grant both overall and allow access, including inherited/conditional grants and deny policies; unknown or unreadable authority fails closed. This does not evaluate principal access boundaries or replace deploy-time checks. Transient policy reads retry three times (5/10-second delays); 4xx and malformed responses fail immediately. Errors identify scope, resource and permission without provider attributes.

The PR identity reads metadata/IAM, the exact default production state object and bucket object names for workspace discovery. It cannot write/lock state, mutate resources, read Secret Manager metadata/policies/versions, sign or impersonate the deployer. Each of the six reviewed secret-bearing `pr_plan_exclusions` emits a notice; static checks and protected planning still apply.

**Same-repository PR authors can read sensitive values persisted in production state.** Forks skip authentication; keep GitHub's fork write-token option disabled because WIF alone cannot distinguish them. Other PR jobs remain credential-free. The separate PR WIF pool requires this repository, `pull_request`, a numeric PR merge ref and exact CI/planner workflow refs. Checkout credentials are not persisted; full history supports comparison-base scope discovery.

Activate through protected `terraform-state-read-iam-sync.yml`: `PR plan identity IAM bootstrap` precedes `PR plan identity provisioning`. Set `GCP_PR_PLAN_SERVICE_ACCOUNT`, then `GCP_PR_PLAN_WORKLOAD_IDENTITY_PROVIDER` from sensitive `github_pr_plan_*` outputs after provisioning. Without the provider variable the job reports **not yet activated**, succeeds without authentication; once configured, auth/plan/allowlist/permission failures block `ci-ready`. Code alone provisions nothing; local apply is prohibited.
