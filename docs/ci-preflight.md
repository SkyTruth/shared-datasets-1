# Complete validation before pushing

## Validate before push

1. Finish focused positive and refusal checks. Real releases require [publication readiness](publication-readiness.md); publication-code changes without a release require complete synthetic runtime/serialization batches and `uv run python scripts/publication_runtime_check.py`.
2. Resolve prerequisites/overlaps with the [integration owner](agent-integration.md), fetch current main and complete any authorized base update. Run `uv run ruff check .` before every commit. Commit only when authorized; use a clean checkout with full history. Freeze code before full validation.
3. Start `uv run python scripts/ci_preflight.py --wait --base <current-main-sha> --head <branch-head-sha>` as a background job with no short caller timeout (at least 15 minutes, or none). Capture its log under a named task directory in the standard temp root. Stop it with SIGINT to the driver, allowing cleanup to finish. Docker must support Linux AMD64/ARM64 execution; production image checks retain AMD64 coverage. Use the locked uv environment.
4. Inspect final evidence/logs. Fix missing tools, failures, empty collection and unexpected relevant skips. Recheck head, main and cleanliness before pushing. A PR's first push and toolchain or validation-contract changes require a full local run. For later commits, add `--since <validated-sha>`: passing local evidence on the same base and contract selects the delta plus always-on suites and records reused suites. If the validated prior receipt uses a different contract, the driver runs the full selection and records no reused coverage; malformed or failed prior receipts still fail. Conflict-free base-only movement, PR-body edits and hosted waits need no local rerun. Hosted `ci-ready` still runs the full current PR selection.

## Isolation and tools

The driver validates an isolated prospective merge under the [standard temp root](standards/local-temp-workspaces.md), preserving index/working tree and isolating Docker configuration and credentials. One kernel lock admits a local driver across worktrees; use `--wait` to queue and record seconds waited. Do not remove the lock or edit/commit in a validating checkout. SIGINT/SIGTERM stop pending suites, interrupt the host image driver and remove this run's labelled containers. Only driver-owned containers carry `shared-datasets-preflight-driver`; standalone image probes keep a separate label. The next slot owner removes abandoned driver-labelled containers and preflight image tags older than 24 hours; failed-run TARs are deleted. Fixed merge dates make a base/head pair reproducible. The coordination directory retains validated local evidence and `preflight-runs.jsonl` with head/base, start/end, slot wait, per-suite seconds and outcome. [`ci_toolchain.py`](../scripts/ci_toolchain.py) pins tools installed by [`ci_install_tools.py`](../scripts/ci_install_tools.py) and the [`ci-tools` action](../.github/actions/ci-tools/action.yml); evidence records commands, resolved paths and versions. Syntax checks require checksum-verified ShellCheck **0.11.0** before actionlint. Hosted selectors use cached setup-uv with Python **3.12.12** and `uv run --frozen --only-group ci-plan`: only locked PyYAML/python-hcl2 and their dependencies. Plain Python remains separate from environments created by `uv sync`. Clean-interpreter tests clear inherited `VIRTUAL_ENV`, sync their declared locked dependencies even with a cold cache, audit workflow/composite imports and execute both selectors through their actual dependency flags. The `tests` and `tests-control-plane` jobs partition all Python test files exactly once; CI and deployment filenames belong to `tests-control-plane`. Both initialize pinned prod providers and use four pytest workers through the same hosted/preflight command builder. Each produces independent evidence required by `ci-ready`. Local execution uses two suite workers, or three when Docker reports at least eight CPUs; production images start first, with browser second on the larger VMs. On smaller VMs, browser runs alone after the other suites finish so its four SwiftShader workers do not compete with parallel pytest processes. Chromium is baked into the preflight image using the browser lockfile and `PLAYWRIGHT_BROWSERS_PATH`. The first failed suite cancels queued work immediately. Workflow import probes batch each distinct program/dependency combination by its declared environment. A separate clean-interpreter check exercises production YAML/HCL parsing with the real libraries, outside pytest's parse cache. Session caches reuse YAML/HCL parses by content and options and return independent copies; collection clocks are constant.

## Selection and offline checks

[`ci_contract.py`](../scripts/ci_contract.py) resolves deployments, validation suites and `production_image_targets` once. Outputs, runners, `ci-ready` and image loaders consume that serialized image list; selected deployments impose an image floor, including hold-only releases. Selection grants no mutation authority.

[The deployment procedure](ci-deployment.md) owns registry/prerequisite and source-selection rules. Image inputs follow actual Docker COPY and installed probes; absent imports add no image inputs. Lockfile/project changes select the five recipes that copy them while retaining all validation suites. Native/browser selection follows Python/relative imports and literal subprocess scripts. Manual-only state-reader/reconciliation remains manual.

Draft PRs run only two shell rejection jobs: required `geospatial-changes` and `ci-ready` fail before checkout/setup, while dependent suites skip. The required set stays blocked for that draft event even on rerun. `ready_for_review` starts fresh validation for the ready event. The four required names remain `lint`, `tests`, `geospatial-changes`, and `ci-ready`.

For `ci.yml`, compare parsed job definitions against the base: select changed suite jobs and both SDK runtimes for `sdk-validation` (Node 22 then Node 24 in one job); shared scheduling/selector/gate changes select all suites. Missing comparison history broadens validation. Unrelated administration keeps lint/Python coverage.

Non-doc lint performs credential-free Terraform init/validate, dependency closure, changed-HCL apply-scope/permission checks and `uv run python scripts/reviewed_dataset_plan.py check-diff --base <base-sha> --head <head-sha>`. Immutable-plan validation checks added committed bytes/path/schema and rejects changes/deletion of existing plans; WDPA build envelopes retain their validator. Dynamic values, instance keys and effective IAM require protected saved-plan/live checks. Offline acceptance never replaces PR approval, source generations or publication prerequisites. Docs-only changes use lightweight diff, secret, catalog-doc and site checks.

## Image execution and hosted evidence

[`production_image_contracts.py`](../scripts/production_image_contracts.py) consumes CPU/memory caps serialized into the tested-tree plan by the shared HCL index, then builds production recipes and executes installed probes without host parser dependencies or network/source mounts. Cloud Run defaults apply only when service resources are unset. Sea ice runs its synthetic conversion once at **2 vCPU / 512 MiB** with memory-backed `/tmp`; WDPA builds both realms. EAMLIS/MPAtlas use [`installed_ingestion_fixture.py`](../scripts/installed_ingestion_fixture.py). Monitoring executes an explicit installed receiver probe; test-module source is never the container payload.

Hosted images use two fail-fast matrix groups: the six short targets share one runner with at most two producers, and WDPA has its own runner. Both retain per-target receipts; local batches also allow two image producers and terminate remaining producers on failure. Local images retain an ID-only `local-daemon` manifest after the same Linux/amd64 installed probes, skipping TAR pack/hash/reload; hosted receipts and deployment loaders still require verified TARs and reject local manifests. Results bind target, SHA/tree, toolchain and exact producing run/attempt. Compact receipts require diagnostic evidence and, push deliveries only, tested TAR uploads. PRs, dispatches and held/nondeploying push targets retain metadata without unconsumed TARs. Only selected push deliveries upload `ci-image-*` TARs, for two days. Docker build record uploads are disabled. Viewer/Slack skip buildx/remote caching; Python is pinned through uv. Evidence hashes cover complete validator/common modules and nested local composites; native fixture tools and browser no-skip/no-retry requirements remain mandatory.

`ci-ready` requires every selected suite/image and both SDK runtimes, proven by successful producing jobs or the verified PR coverage below, and checks exact-head owner acceptance in the same job. The refresh callback reruns only that gate after relevant approval or dismissal, or a failed PR CI completion; successful CI completions allocate no refresh runner. Only its successful completion exposes the main-push delivery map; the shared output retains the main-push guard and callers reject a failed ancestor or a cancelled direct prerequisite while permitting unselected skips. Missing, stale, failed, cancelled or unexpectedly skipped evidence fails. Same-run selective reruns preserve exact attempt proof. Historical receipts remain readable, loaders never rebuild missing bytes, and diagnostic/compact artifacts last 14 days; deploying image TARs last two days. PRs cancel obsolete graphs; main/dispatch evidence and mutation locks remain independent.

On the first attempt of a main push, [`ci_main_reuse.py`](../scripts/ci_main_reuse.py) looks up the commit's associated PRs under one 60-second deadline covering metadata requests, retries and the archive download. Expiry terminates the active transport and selects full validation. Exactly one must be a merged same-repository PR targeting main with `merge_commit_sha` equal to the pushed SHA. Its latest CI run must be a successful `pull_request` run with successful `ci-ready` and one digest-verified, unexpired evidence artifact from that gate execution. The evidence must match the pushed tree, push `before` base, current contract digest, selected suites and toolchain identities. Tree equality means the evidence was produced by the same workflow files that main runs. Dispatch and fork runs cannot qualify. The PR evidence contains its base/head/tested merge/tree identities, PR/event/repository, run/attempt, selected suites, tools and result summaries, retained for 14 days.

A match skips lint, both Python partitions, browser and native validation at job level. The selection and its image targets remain intact; selected production images and both selected SDK runtimes execute on main and retain their original delivery authorization. After lookup completes, the successful selector checks freshness and records `admitted_at` with the small API/artifact snapshot in its immutable plan. The gate checks expiry against that authenticated admission time, so evidence expiring while main jobs run does not invalidate admitted coverage. The gate verifies that snapshot against the current checkout, event, source selector attempt and toolchains before accepting skips, then records the original PR/run/attempt and matched identities in `ci-ready-evidence`; reused summaries retain their original producing identities. Lookup/API/archive errors and every mismatch select full validation. No extra lookup runner or no-op suite runners are allocated.

All-job main reruns deliberately disable PR reuse and execute the full selection, including when PR evidence has expired. A selective rerun of a gate that used PR coverage cannot reinterpret its previous skipped jobs: use **Re-run all jobs**. Proofs that were expired at admission, lack an admission timestamp or have altered identities fail explicitly at the gate; they never authorize delivery. Original successful gate receipts and exact image/SDK attempt proofs remain usable by the existing delivery/recovery readers.

## Holds, failures and retries

Holds retain validation/images while blocking deployment; [alert routing](alert-routing.md#scheduled-freshness-and-capacity) owns hold/pause schema, expiry and health checks. Clock expiry does not change selection or fail `ci-ready`. Reviewed hold removal selects its deployment/image on the next main push; historical bare hold lists are comparison baselines only. Follow [recovery](ci-recovery.md) for bounded hosted retries and [deployment contracts](deployment-contracts.md#serialization-and-protected-execution) for pre-mutation lock/plan-read retries. Neither authorizes replay of an uncertain mutation. The independent safety health report also deduplicates a disabled incident switch or missing bot token through its webhook, including changed findings and daily reminders.
