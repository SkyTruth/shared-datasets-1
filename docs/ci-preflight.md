# Complete validation before pushing

## Validate before push

1. Finish focused positive and refusal checks. Real releases require [publication readiness](publication-readiness.md); publication-code changes without a release require complete synthetic runtime/serialization batches and `uv run python scripts/publication_runtime_check.py`.
2. Resolve prerequisites/overlaps with the [integration owner](agent-integration.md), fetch current main and complete any authorized base update. Commit only when authorized; use a clean checkout with full history. Freeze code before full validation.
3. Run `uv run python scripts/ci_preflight.py --base <current-main-sha> --head <branch-head-sha>`. Docker must support Linux AMD64/ARM64 execution; production image checks retain AMD64 coverage. Use the locked uv environment.
4. Inspect final evidence/logs. Fix missing tools, failures, empty collection and unexpected relevant skips. Recheck head, main and cleanliness before pushing. Revalidate subsequent pushes after code, base, toolchain or contract changes; PR-body edits and waiting on hosted checks need no repeated run.

## Isolation and tools

The driver validates an isolated prospective merge under the [standard temp root](standards/local-temp-workspaces.md), preserving index/working tree and isolating Docker configuration and credentials. One nonblocking kernel lock admits a local driver across worktrees. Busy is failure with an owner: do not remove the lock, poll or edit/commit in a validating checkout. Inspect surviving process-owned Docker work after process death. [`ci_toolchain.py`](../scripts/ci_toolchain.py) pins tools installed by [`ci_install_tools.py`](../scripts/ci_install_tools.py) and the [`ci-tools` action](../.github/actions/ci-tools/action.yml); evidence records commands, resolved paths and versions. Syntax checks require checksum-verified ShellCheck **0.11.0** before actionlint. Hosted selectors use cached setup-uv with Python **3.12.12** and `uv run --frozen --only-group ci-plan`: only locked PyYAML/python-hcl2 and their dependencies. Plain Python remains separate from environments created by `uv sync`. Clean-interpreter tests clear inherited `VIRTUAL_ENV`, sync their declared locked dependencies even with a cold cache, audit workflow/composite imports and execute both selectors through their actual dependency flags. The `tests` and `tests-control-plane` jobs partition all Python test files exactly once; CI and deployment filenames belong to `tests-control-plane`. Both initialize pinned prod providers and use four pytest workers through the same hosted/preflight command builder. Each produces independent evidence required by `ci-ready`. Workflow import probes batch each distinct program/dependency combination by its declared environment. A separate clean-interpreter check exercises production YAML/HCL parsing with the real libraries, outside pytest's parse cache. Session caches reuse YAML/HCL parses by content and options and return independent copies; collection clocks are constant.

## Selection and offline checks

[`ci_contract.py`](../scripts/ci_contract.py) resolves deployments, validation suites and `production_image_targets` once. Outputs, runners, `ci-ready` and image loaders consume that serialized image list; selected deployments impose an image floor, including hold-only releases. Selection grants no mutation authority.

[The deployment procedure](ci-deployment.md) owns registry/prerequisite and source-selection rules. Image inputs follow actual Docker COPY and installed probes; absent imports add no image inputs. Lockfile/project changes select the five recipes that copy them while retaining all validation suites. Native/browser selection follows Python/relative imports and literal subprocess scripts. Manual-only state-reader/reconciliation remains manual.

Draft PRs run only two shell rejection jobs: required `geospatial-changes` and `ci-ready` fail before checkout/setup, while dependent suites skip. The required set stays blocked for that draft event even on rerun. `ready_for_review` starts fresh validation for the ready event. The four required names remain `lint`, `tests`, `geospatial-changes`, and `ci-ready`.

For `ci.yml`, compare parsed job definitions against the base: select changed suite jobs and both SDK runtimes for `sdk-validation` (Node 22 then Node 24 in one job); shared scheduling/selector/gate changes select all suites. Missing comparison history broadens validation. Unrelated administration keeps lint/Python coverage.

Non-doc lint performs credential-free Terraform init/validate, dependency closure, changed-HCL apply-scope/permission checks and `uv run python scripts/reviewed_dataset_plan.py check-diff --base <base-sha> --head <head-sha>`. Immutable-plan validation checks added committed bytes/path/schema and rejects changes/deletion of existing plans; WDPA build envelopes retain their validator. Dynamic values, instance keys and effective IAM require protected saved-plan/live checks. Offline acceptance never replaces PR approval, source generations or publication prerequisites. Docs-only changes use lightweight diff, secret, catalog-doc and site checks.

## Image execution and hosted evidence

[`production_image_contracts.py`](../scripts/production_image_contracts.py) consumes CPU/memory caps serialized into the tested-tree plan by the shared HCL index, then builds production recipes and executes installed probes without host parser dependencies or network/source mounts. Cloud Run defaults apply only when service resources are unset. Sea ice runs its synthetic conversion once at **2 vCPU / 512 MiB** with memory-backed `/tmp`; WDPA builds both realms. EAMLIS/MPAtlas use [`installed_ingestion_fixture.py`](../scripts/installed_ingestion_fixture.py). Monitoring executes an explicit installed receiver probe; test-module source is never the container payload.

Hosted images use two fail-fast matrix groups: the six short targets share one runner with at most two producers, and WDPA has its own runner. Both retain per-target receipts; local batches also allow two producers and terminate remaining producers on failure. Results bind target, SHA/tree, toolchain and exact producing run/attempt. Compact receipts require diagnostic evidence and, push deliveries only, tested TAR uploads. PRs, dispatches and held/nondeploying push targets retain metadata without unconsumed TARs. Only selected push deliveries upload `ci-image-*` TARs, for two days. Docker build record uploads are disabled. Viewer/Slack skip buildx/remote caching; Python is pinned through uv. Evidence hashes cover complete validator/common modules and nested local composites; native fixture tools and browser no-skip/no-retry requirements remain mandatory.

`ci-ready` requires every selected suite/image and both SDK runtimes, proven by successful producing jobs, and checks exact-head owner acceptance in the same job. The refresh callback reruns only that gate after relevant approval or dismissal, or a failed PR CI completion; successful CI completions allocate no refresh runner. Only its successful completion exposes the main-push delivery map; the shared output retains the main-push guard and callers reject a failed ancestor or a cancelled direct prerequisite while permitting unselected skips. Missing, stale, failed, cancelled or unexpectedly skipped evidence fails. Same-run selective reruns preserve exact attempt proof; cross-run reuse is unsupported. Historical receipts remain readable, loaders never rebuild missing bytes, and diagnostic/compact artifacts last 14 days; deploying image TARs last two days. PRs cancel obsolete graphs; main/dispatch evidence and mutation locks remain independent.

## Holds, failures and retries

Holds retain validation/images while blocking deployment; [alert routing](alert-routing.md#scheduled-freshness-and-capacity) owns hold/pause schema, expiry and health checks. Clock expiry does not change selection or fail `ci-ready`. Reviewed hold removal selects its deployment/image on the next main push; historical bare hold lists are comparison baselines only. Follow [recovery](ci-recovery.md) for bounded hosted retries and [deployment contracts](deployment-contracts.md#serialization-and-protected-execution) for pre-mutation lock/plan-read retries. Neither authorizes replay of an uncertain mutation. The independent safety health report also deduplicates a disabled incident switch or missing bot token through its webhook, including changed findings and daily reminders.
